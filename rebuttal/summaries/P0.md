## Caveats found during validation

1. **Facility-location baseline code is not in the repo.** Only its outputs
   (`sweep_cluster_k/baseline_comparison_lpips_ks/baseline_min_size_summary.csv`,
   `baseline_sweep_results.csv`) and config (`baseline_eval_config.json`:
   M=400, seed 0, `facility_candidate_pool=16`) exist; audit scripts consume
   it as "summary only". Any task needing to *re-run* facility location would
   require reimplementation from the config.
2. **Effective Zip-NeRF audit population is 3,521, not 3,522**: descriptor
   scene `dish_1563900172` has no Zip-NeRF log entry. The paper's own
   exported artifacts use 3,521 (`full_count=3521`), so the reproduction
   targets are unaffected; the stated constant has a documented off-by-one.
3. **Instant-NGP PSNR column convention.** The paper's cross-method table
   uses the per-frame-mean PSNR columns (`PNSR` in `ingp_fi.csv`, `PSNR` in
   `ingp_oc.csv`); the strong-accept canonicalizer prefers the MSE-aggregated
   `psnr avgmse` columns. Only the per-frame-mean convention reproduces the
   references (FI 0.0840 vs 0.1095 under avgmse; OC 0.1092 vs 0.0344). The
   earlier `multi_method_frontier` task used the avgmse convention (as
   stated in its summary); its Instant-NGP PSNR event therefore follows the
   canonicalizer's convention, not the paper table's. Both values are
   recorded in the P0 JSON.

Initial run failed the two Instant-NGP PSNR checks under the avgmse
convention; after diagnosing the column divergence (population means match
the paper reference file exactly under the per-frame-mean columns), the
checks were recomputed under the paper convention and pass. No data or code
changes were made to the pipeline itself.

Artifacts: `rebuttal_results.json` key `P0`; validation script
`scripts/rebuttal_p0_validation.py` (deterministic, seed 0).
